This problem hits at some core parts of RL and introduces several core techniques:

1. Exploration vs. Exploitation - how do you balance trying to find the best bandit to use while also trying to maximize profit?
2. Stationary vs. Nonstationary distributions - can the distribution of rewards or actions change over time? If so, which algorithms are no longer effective?
3. Exact vs. Scalable - For a given problem, you may be able to calculate the gradient correctly, but it's impractical, if possible at all, to do this for larger problems with trillions of potential states.

# Terminology

This is a bit of a retread of the book, but we'll define a few key terms here first. We define the action-value (the estimated value of our actions) as the following:

$$
Q_t(a)
\mathrel{\dot{=}} \frac{\text{sum of rewards when $a$ taken prior to $t$}}{\text{number of times $a$ taken prior to $t$}}
= \frac{\sum_{i=1}^{t-1} R_i \cdot \mathbb{1}_{A_i = a}}{\sum_{i=1}^{t-1} \mathbb{1}_{A_i = a}}
$$

This is just a normal sample average and a natural way to think about the rewards we receive for each action that we take (applying equal weight to each sample). A purely exploitative, or greedy, action selection would be:

$$
A_t \mathrel{\dot{=}} \argmax_a Q_t(a)
$$

Another approach is to pick a non-optimal strategy with probability $\epsilon$, meaning that we will always perform some exploration and won't get caught in local extrema. There are certainly more effective ways that we will consider in the future, but just this simple change will have a profound impact on the results as we will see.

## Establishing an Upper Bound

Given this parameterization, we can also calculate the asymptote for the expected return of our bandit player in the long run. That is to say we want to compute

$$
\mathbb{E}[M_n] = \mathbb{E}\left[\max_i X_i\right]
$$

where $X_i \overset{iid}{\sim} \mathcal{N}(0,1)$. We need the PDF of $M_n$ to calculate the expectation, but we must first derive the CDF from the definition of the max and our i.i.d. restriction.

$$
F_{M_n}(m)
= P(M_n \leq m)
= P(X_1 \leq m, X_2 \leq m, \dots, X_n \leq m)
= P(X_1 \leq m) \cdot \cdots \cdot P(X_n \leq m)
= F(m)^n
$$

Next, we will take the derivate to compute the CDF via chain rule.

$$
f_{M_n}(m)
= \frac{d}{dm} F_{M_n}(m)
= \frac{d}{dm} F(m)^n
= n F(m)^{n-1} f(m)
$$

Finally, we can calculate

$$
\mathbb{E}[M_n]
= \int_{-\infty}^{\infty} x f_{M_n} (x) dx
= \int_{-\infty}^{\infty} x \cdot n F(x)^{n-1} f(x) dx
\approx 1.55
$$

This integral is particularly difficult to calculate for Gaussians, but it's common enough that we can find a good upper bound estimate online for $1.55$. This means that if we average our incremental rewards over all runs, we would expect that a good solution to the bandit problem would quickly approach this asymptote without going over it. It also serves as a good debugging tool when you see algorithms achieving incremental rewards that shouldn't be possible...

### The Bandit Solver

We'll begin with the following abstract class to represent our Bandit Solver algorithms:

```python
class BanditSolver(ABC):
    @abstractmethod
    def select_action(self):
        pass
    
    @abstractmethod
    def update(self, action, reward):
        pass
```

So far, we've only seen the action-value method, which incrementally computes the return estimate as:

$$
Q_{n+1} = Q_n + \frac{1}{n} (R_n - Q_n)
$$

We've also seen the adaptation that treats the update step as an EMA, which can be particularly useful for non-stationary distributions as we will see momentarily.

$$
Q_{n+1} = Q_n + \alpha (R_n - Q_n)
$$

Additionally, we've seen the $\epsilon$-greedy approach to action selection, which at every step either selects the greedy choice (that which maximizes the estimated returns) or randomly selects from any of the options. Putting all of this together, we get the following:

```python
class EpsilonGreedyBanditSolver(BanditSolver):
    def __init__(self, k, eps, eps_decay=None, alpha=None, init_val=0):
        self.k = k
        self.return_ests = np.zeros(k) + init_val
        self.action_counts = np.zeros(k)
        self.alpha = alpha
        self.eps = eps
        self.eps_decay = eps_decay

    def select_action(self):
        if rng.random() < self.eps:
            # Explore: select a random action
            selected_action =  rng.integers(self.k)
        else:
            # Exploit: select the action with the highest expected payoff
            selected_action = np.argmax(self.return_ests)
        self.eps *= self.eps_decay if self.eps_decay else 1
        return selected_action
    
    def update(self, action, reward):
        self.action_counts[action] += 1
        weight = self.alpha if self.alpha is not None else 1 / self.action_counts[action]
        self.return_ests[action] += weight * (reward - self.return_ests[action])
```

The Solver maintains its estimates of the running returns and the number of times each action has been selected so that we can incrementally update our estimates. It also supports the sample-average and EMA implementation as discussed before. In future experiments, we can also consider how the results might change if we randomly sample from all leading candidates rather than taking the first instance of the max value that we find.
